# WukongBench

Консольный инструмент на C# для полностью автоматического запуска **Black Myth: Wukong Benchmark Tool** (Steam, App ID `3132990`).

Инструмент сам делает два прохода бенчмарка с разными настройками графики:

1. **CPU-тест**: нагрузка максимально смещена на процессор.
2. **GPU-тест**: максимальная нагрузка на видеокарту.

После каждого прохода он получает результаты от самого бенчмарка и в конце выводит в консоль таблицы: характеристики компьютера, результаты двух тестов и использованные настройки.

## Требования

- Windows 10/11
- .NET SDK (проект собирался на .NET 10, `net10.0-windows`; для другой версии поменяй `TargetFramework` в `WukongBench.csproj`)
- Steam запущен, **Black Myth: Wukong Benchmark Tool** установлен и хотя бы раз запускался (чтобы существовал файл настроек)
- Основной монитор 16:9 (проверено на 1920×1080), игра в режиме «Без рамки» (по умолчанию)

## Запуск

Открыть проект в Visual Studio и запустить (F5). `config.json` должен лежать рядом с exe (в проекте он копируется в папку сборки автоматически).

Во время работы **не трогайте мышь и клавиатуру**: инструмент управляет меню игры эмуляцией ввода. Один проход занимает несколько минут (загрузка игры, сам бенчмарк, закрытие).

## Как это работает

1. **Настройки.** Бенчмарк читает `GameUserSettings.ini` (`%LOCALAPPDATA%\b1\Saved\Config\...`). Инструмент находит файл, делает бэкап и перед каждым проходом подставляет значения профиля из `config.json`. В файле часть настроек лежит в одной длинной строке `UISettingData=(("Ключ", "Значение"), ...)`, часть в обычных строках (`sg.*` и др.), поэтому правятся оба вида. В конце исходный файл восстанавливается, даже если произошла ошибка.
2. **Запуск.** Через `steam://rungameid/3132990`. Для ноутбуков с двумя видеокартами на время работы выставляется предпочтение дискретной GPU (в реестре, как «Параметры → Дисплей → Графика → Высокая производительность»), после работы значение возвращается.
3. **Меню.** Игра пропускает ввод с эмулированной клавиатуры, поэтому меню проходится мышью: клики по относительным координатам окна (доли от его размера, поэтому работает на разных разрешениях 16:9). Сначала повторяющиеся клики в центр окна («нажмите любую клавишу» на экране загрузки), затем клик по кнопке **Benchmark**. Окно игры при этом принудительно выводится на передний план.
4. **Результаты.** По окончании теста бенчмарк пишет JSON-файл в `%TEMP%\b1\BenchMarkHistory\Tool\<unix-время>`. Инструмент запоминает список файлов до запуска, ждёт появления нового, дожидается окончания записи и разбирает его. Из файла берутся FPS (средний, максимальный, минимальный, 95%), VRAM, железо, настройки графики и покадровые замеры (FPS, время кадра CPU и GPU).
5. **Закрытие.** К этому моменту результаты уже записаны, поэтому программа завершается принудительно. В коде есть и выход через меню (`gracefulExit` и `exitSteps` в `config.json`), но по умолчанию он выключен: положение кнопок подтверждения не настроено.
6. **Железо** дополнительно собирается через WMI: CPU, все видеокарты, RAM, ОС, модель ноутбука, питание от сети или батареи.

## Выбор настроек

В обоих тестах включён апскейлер **TSR** и выключены **генерация кадров** и **полная трассировка лучей**. TSR встроен в движок и работает на любой видеокарте, поэтому результаты сопоставимы между машинами (DLSS есть не у всех). Генерация кадров искажает FPS, потому что часть кадров рисуется искусственно. Трассировку на видеокарте без RT-ядер (GTX 1650) включать невозможно.

### CPU-тест

Цель: основная нагрузка на процессор, влияние видеокарты минимально.

| Настройка | Значение | Почему |
|---|---|---|
| Степень избыточной выборки сглаживания | 33% | игра рендерит в ~640×360 и растягивает картинку, это резко снижает работу GPU |
| Набор настроек графики | Низкое | тени, освещение, отражения, постобработка, сглаживание, текстуры и эффекты считаются на GPU |
| Детализация объектов вдали, качество растительности | Низкое | см. примечание ниже |
| Размытие при движении | Выкл | постобработка = нагрузка на GPU |

Примечание. Изначально дальность прорисовки и растительность стояли на максимуме в расчёте на нагрузку CPU (больше объектов для отсечения и draw calls). На тестовом ноутбуке со слабой GTX 1650 минимальные значения дали лучший результат для CPU-теста, потому что видеокарта оставалась узким местом. Профиль подобран эмпирически, а не по теории. На мощной видеокарте может иметь смысл вернуть дальность и растительность выше.

### GPU-тест

Цель: максимальная нагрузка на видеокарту.

| Настройка | Значение | Почему |
|---|---|---|
| Степень избыточной выборки сглаживания | 100% | нативное разрешение, максимум пикселей |
| Набор настроек графики | Реалистичное (уровень 5, максимум) | максимальная нагрузка на шейдеры и видеопамять |
| Размытие при движении | Очень заметные | дополнительная постобработка |
| Разрешение экрана | 1920×1080 | нативное разрешение дисплея |

### Проверка выбора настроек

В таблице результатов есть среднее время кадра CPU и GPU и строка **«Ограничивало»**: она определяется сравнением этих значений (чем больше время, тем сильнее компонент тормозит кадр). Для CPU-теста ожидается «CPU», для GPU-теста «GPU». Дополнительно профили проверялись вручную по диспетчеру задач.

Загрузка CPU и GPU, которую бенчмарк пишет в свой файл, ненадёжна: в моих замерах `CPUUsage` был ровно 1 во всех замерах подряд и не совпадал с диспетчером задач. Поэтому за основу взято время кадра, а эти две строки в отчёте помечены как «по данным бенчмарка».

## Структура проекта

| Файл | Назначение |
|---|---|
| `Program.cs` | точка входа: бэкап настроек, два профиля, восстановление, вывод отчёта |
| `Runner.cs` | запуск одного прохода: Steam, меню, ожидание результата, закрытие игры |
| `Keyboard.cs` | эмуляция ввода (SendInput): клики мышью и клавиши, вывод окна на передний план |
| `BenchFile.cs` | поиск и разбор JSON-файла с результатами бенчмарка |
| `IniEditor.cs` | правка `GameUserSettings.ini` (включая строку `UISettingData`) |
| `SteamHelper.cs` | поиск установки игры, предпочтение дискретной видеокарты |
| `SystemInfo.cs` | характеристики компьютера через WMI |
| `Reporter.cs` | вывод таблиц в консоль |
| `Models.cs` | модели данных |
| `config.json` | профили настроек, сценарий прохождения меню, таймауты |

## Настройка под свой компьютер

Всё, что может отличаться, лежит в `config.json`:

- `profiles`: значения настроек обоих тестов;
- `startSteps`: сценарий прохождения меню. Шаг `Click` принимает координаты `x`, `y` как доли окна (0..1), `delayBeforeMs` (пауза перед шагом), `repeat` и `repeatDelayMs` (повторы). Если игра у тебя грузится дольше, увеличь задержки;
- `launchTimeoutSec`, `benchmarkTimeoutSec`: таймауты ожидания;
- `gracefulExit`, `exitSteps`: выход через меню вместо принудительного закрытия.

## Ограничения

- Формат файла результатов в `%TEMP%` разработчиками не документирован. Он описан по наблюдению за версией 1.0.3.14649 и может измениться в других версиях.
- Координаты кнопки Benchmark заданы по раскладке меню 16:9 и проверены на 1920×1080. Для другого соотношения сторон их нужно поправить в `config.json`.
- Игра игнорирует ввод с эмулированной клавиатуры, поэтому управление идёт мышью. Если игра запущена от администратора, а инструмент нет, ввод не дойдёт: запускай оба с обычными правами.
- Профили подобраны под видеокарту без аппаратной трассировки. На RTX-картах GPU-профиль стоит усилить, включив трассировку.
- Проверено только на одном ноутбуке (характеристики выше).
